# 💒 离线婚礼桌位编排器

宾客关系 **与** 真实场地布局一起规划的纯前端应用，全程无服务端：

- **React + TypeScript**：宾客侧栏（出席状态、家庭、忌口、关系）
- **Konva（react-konva）**：绘制圆桌/长桌、座位、过道与消防出口禁止多边形，支持拖拽布局与拖拽换座
- **glpk.js（WebAssembly）在 Web Worker 中求解 MILP**：同桌、分桌、容量、锁定约束
- **IndexedDB（idb）**：工程本地自动保存，可导出/导入 JSON
- **桌卡导出**：CSV（Excel 带 BOM）/ 可打印 HTML，忌口信息独立于席位存储，换座不丢

## 快速开始

```bash
npm install
npm run dev        # 开发
npm run build      # 类型检查 + 生产构建（dist/ 为纯静态资源，可离线托管）
npm run preview    # 本地预览构建产物

npm test           # Node 求解器 + 几何测试（真实 glpk.js WASM）
npm run e2e        # Playwright 端到端（需先 npm run preview）
```

`npm run build` 后 `dist/` 不依赖任何后端；放到任意静态目录即可运行。
所有数据只存于浏览器 IndexedDB 与你主动导出的文件中。

## 约束模型（`src/lib/solverCore.ts`）

每位活跃宾客对每一张桌有 0/1 变量 `x[g,t]`。

**硬条件（不满足则拒绝排座，`src/lib/model.ts` 的 `preDiagnose` 先做无需求解的预检）：**

- 家庭同行 → 家庭成员两两**必须同桌**：`x[a,t] = x[b,t]`
- 显式避让 → **必须分桌**：`x[a,t] + x[b,t] ≤ 1`
- 容量：`Σ 非锁定客 x ≤ 座位数 − 锁定座位数`
  - 锁定座位上的宾客模型中只有原桌变量，**自动排座无法移动**
  - 锁定的**空座**计入扣除，用作儿童椅/预留位占位
- 锁定冲突（必须同桌却锁在不同桌、必须分桌却锁同桌）直接报告
- 同组人数超过任何单桌容量、总容量不足 → 报告

**软条件（可放宽，进入目标函数并在 UI 显示代价）：**

| 偏好 | 代价 | 松弛变量含义 |
|---|---|---|
| 希望同桌 like | 20/对 | 未同桌时 =1 |
| 希望分开 dislike | 25/对 | 同桌时 =1 |
| 靠近主桌 | 5 × 距离档 | 按到主桌欧氏距离排序分档 |
| 未排座（容量兜底松弛） | 100/人 | 仅预检未覆盖的极端情况，名单会列出 |

预检已覆盖常见无解（矛盾三角、锁定冲突、容量不足、同组超大）。
自动方案**先预览不落地**：面板显示代价明细，可"与当前手工方案比较"、应用或丢弃；
应用本身进入撤销栈，`Ctrl/Cmd+Z` 可退回手工方案再对比。

## 操作

- **手工入座**：侧栏点选宾客 → 点击场地座位；有人时交换座位；也可直接拖动座位姓名
- **锁定/解锁座位**：`Shift+点击座位`（锁空座 = 儿童椅占位，自动排座既不会放入宾客也不会移动）
- **撤销/重做**：`Ctrl+Z` / `Ctrl+Shift+Z`（所有手工操作与布局操作均可撤销）
- **布局模式**：拖桌子、加桌、改容量/形状/主桌标记、锁定桌子几何位置
- **未回复宾客**：RSVP=pending 默认不参与自动排座，工具栏开关可纳入
- **同名宾客**：`nameSeq` 为稳定序号（删除他人不重排），界面显示如「王芳 ②」
- **忌口**：直接挂在宾客上，与席位完全独立；桌卡导出时现取，任何换座后导出都不丢

## 禁止占用多边形与安全说明

场地中的过道、消防出口缓冲区以项目提供的多边形（`ForbiddenZone.points`）表示。
系统仅做**纯几何相交检查**：桌子占地多边形（桌面 + 28px 椅子余量）与禁止区相交、
或桌间占地重叠时在画布红框警示并列 HUD。

> ⚠️ 该检查只是几何提示，**不声称、也不构成任何消防/疏散/安全认证**。
> 实际桌位布置必须由场地与安全负责方确认。

## 演示样例与验证

工具栏「载入样例」或首屏按钮可载入：

- **冲突无解样例**：李四与张三硬同桌、张母与李四硬分桌，而张三与张母因家庭硬同组 → 三角矛盾，
  自动排座被拦截并列出原因；另含锁定位置冲突
- **儿童椅占位**：主桌锁定 5 个座位（含 1 个空占位），求解器按 8−5=3 的剩余容量排座
- **部分宾客未回复**：赵父、孙七为 pending，默认不参与，勾选后参与
- 同名「王芳 ①/②」、多个忌口（素食/海鲜过敏/清真）、靠近主桌偏好、过道与消防出口多边形

`npm test`（Node + 真实 glpk WASM，5 个场景）：

1. 冲突关系 → 预检判无解并给原因
2. 解除冲突 → 可解、锁定不动、家庭同桌、儿童椅占位扣减容量
3. pending 开关
4. 容量收紧 → 松弛变量报告未排座且代价计入
5. 软偏好被迫放宽（两人希望同桌但只有两张单座桌）→ 可解、like 代价=20

`scripts/geometry-smoke.mjs`：点在多边形、凹形过道、圆/长桌占地、椅子余量、样例不压区。

`npm run e2e`（真实 Chromium，16 项）：冲突拦截、手工入座与撤销、锁定空座排座后仍空、
锁定宾客不动、Worker 求解代价面板、方案比较、IndexedDB 落盘、换座后导出 CSV 忌口不丢、控制台无错误。

## 目录结构

```
src/
  types.ts               数据模型 / Worker 消息
  lib/
    geometry.ts          多边形几何（点包含、相交、桌占地、座位坐标）
    model.ts             工程 -> MILP 输入 + 硬冲突预检
    solverCore.ts        MILP 建模与求解（Worker/Node 共用，常量内置）
    solver.worker.ts     glpk.js Worker 封装
    apply.ts             方案合并（锁定座位原样保留）
    seatingOps.ts        手工落座/移除/锁定/宾客增删（可撤销）
    evaluate.ts          手工方案软代价与硬违反检查
    exportCards.ts       桌卡 CSV/HTML 导出（忌口随宾客）
    sample.ts            演示样例工程
    db.ts                IndexedDB 持久化 / JSON 下载
  state/                 React store（撤销/重做、方案暂存）、Worker 客户端
  components/            宾客侧栏、关系面板、Konva 画布、桌子编辑、方案/比较弹窗
scripts/
  solver-smoke.mjs       Node 求解器场景测试
  geometry-smoke.mjs     几何测试
  e2e.mjs                Playwright 端到端
```
